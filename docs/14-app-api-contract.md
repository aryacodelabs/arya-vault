# 14: App <-> Core API Contract (v1 draft)

**Status:** Draft for owner review. **This is the single source of truth** between the Rust FFI crate (`core/crates/ffi`, tasks A04) and the Flutter app's Dart `VaultApi` interface (tasks B01-B03). Neither side may deviate; changes go through a doc PR first.

Principles (from `docs/02` §8, `docs/04` §11): coarse-grained operations; **no raw keys ever cross the boundary**; list/summary DTOs contain **no secrets**; secrets are returned only by explicit `reveal*`/generate calls and as bytes, not long-lived strings; the core owns all validation.

## 1. Conventions
- All operations are **async** in Dart and are serialized per session by the core (one writer).
- IDs (`ItemId`, `FolderId`, `ElementId`) are opaque 16-byte values, represented in Dart as lowercase hex `String`s (32 chars).
- Timestamps: `int` milliseconds since the Unix epoch (UTC).
- Secret values cross as `Uint8List` (UTF-8). The Dart side must wipe (`fillRange(0)`) after use; a `SecretBytes` helper exists in the app (B01). Honest limit: once a secret is rendered as a Flutter `String`/widget, Dart cannot wipe it; the UI keeps such lifetimes short (reveal auto-hides, doc 07 §7).
- Enums are serialized as Dart enums generated by `flutter_rust_bridge`; names below are canonical.

## 2. Errors
Every call can throw `AppError { code: AppErrorCode, message: String, field: String? }`. `message` is safe to show or log: **never** contains secrets.

| `AppErrorCode` | Meaning / UI behavior |
|---|---|
| `wrongCredentials` | Wrong master password or recovery key (indistinguishable from header/db mismatch by design) |
| `recoveryKeyMalformed` | Typo/bad checksum; ask to re-enter |
| `weakPassword` | Master password fails policy; `message` carries reasons |
| `locked` | Operation requires an unlocked session |
| `notFound` | Item/folder id unknown |
| `validation` | Input rejected; `field` names the field |
| `limitReached` | Field/item/size limit (doc 05 §10) |
| `corruptVault` | Authentication or integrity failure of vault data; show diagnostic export option |
| `unsupportedFormat` | Newer format than this app understands: "update required" mode |
| `quickUnlockUnavailable` | Hardware/OS key missing, policy expired (72 h / reboot / failures) or invalidated; fall back to password |
| `alreadyExists` / `io` / `busy` / `internal` | Self-explanatory; `internal` carries an opaque code, no details |

## 3. Types (DTOs)
```
VaultStatus   { exists: bool, locked: bool, onboardingComplete: bool, formatVersion: int,
                quickUnlock: QuickUnlockStatus }
QuickUnlockStatus { supported: bool, enabled: bool, kind: none|windowsHello|touchId|faceId|biometric|osKeyring }

ItemType      = login | note | card | identity

                | cardCvv | cardPin | ... (exactly the core `StdField` set; see core/crates/vault/src/model.rs)

ItemSummary   { id, type, title, subtitle(username/holder/first-line), favorite, folderId?, tags[], updatedAt,
                hasTotp: bool, deleted: bool }                                   // NO secrets
ItemView      { id, type, title, folderId?, favorite, tags[], urls[UrlView{id,url}], custom[CustomView{id,label,
                kind: text|hidden|url|date, valueIfNotHidden?}], fields: Map<StdField,String?> (non-secret ones
                only), secretFieldsPresent: Set<StdField>, createdAt, updatedAt, otherVersions: bool }
NewItem       { type, title, fields: Map<StdField,String>, urls[], tags[], folderId?, custom[...] }
ListFilter    { types?, folderId?, tag?, favoritesOnly, includeTrash }
Page          { offset, limit }                          // limit <= 200
SearchQuery   { text, filter: ListFilter, page: Page }
Folder        { id, name, parentId? }
TrashEntry    { summary: ItemSummary, deletedAt, purgesAt }
VersionInfo   { field, hlcMs, deviceName?, isCurrent, concurrent: bool }      // history list, values via reveal
PasswordOptions / PassphraseOptions / Strength / PolicyResult   // mirror core `generator` types
HealthReport  { reused: [ReuseGroup{itemIds[]}], weak: [WeakPassword{itemId, score}], old: [OldPassword{itemId, ageDays}] }
```

`ItemSummary`/`ItemView` never contain `password`, `totpSeed`, card number/cvv/pin or note body; those are fetched with `reveal`. `fields` in `ItemView` contains non-secret standard fields only (e.g. title, username, cardHolder, cardExpiry).

## 4. Operations (the Dart `VaultApi` interface)

### 4.1 Lifecycle and credentials
| Operation | Signature (Dart) | Notes |
|---|---|---|
| `status` | `Future<VaultStatus> status()` | Works while locked |
| `createVault` | `Future<RecoveryKeyResult> createVault({Uint8List password, KdfProfile profile})` -> `RecoveryKeyResult{ recoveryKey: Uint8List, groups: int }` | Vault is created **unlocked**; recovery key is returned **once**; `onboardingComplete = false` until `confirmRecoveryKey` passes |
| `confirmRecoveryKey` | `Future<bool> confirmRecoveryKey(List<GroupAnswer{index:int, text:String}> answers)` | Core compares with the pending key it still holds in memory (3 random groups, doc 07 §3 step H); on success sets `onboardingComplete`; on failure returns `false` (UI re-shows key). No retries limit. |
| `unlock` | `Future<void> unlock(Uint8List password)` | Throws `wrongCredentials`; applies local failure-delay (cosmetic, doc 07 §4) |
| `unlockQuick` | `Future<void> unlockQuick()` | Uses the platform quick-unlock provider **inside Rust** (the raw vault key never reaches Dart); throws `quickUnlockUnavailable` |
| `lock` | `Future<void> lock()` | Zeroizes keys, closes DB. Idempotent |
| `changePassword` | `Future<void> changePassword({Uint8List oldPassword, Uint8List newPassword, bool rotateKeys})` | `rotateKeys=true` = "Change password and rotate keys" (SEC-A06) |
| `recoverWithKey` | `Future<void> recoverWithKey({Uint8List recoveryKey, Uint8List newPassword})` | Leaves vault unlocked; doc 04 §9 |
| `regenerateRecoveryKey` | `Future<RecoveryKeyResult> regenerateRecoveryKey({Uint8List password, bool rotateKeys})` | Sets `onboardingComplete=false` until confirmed again |
| `quickUnlockEnable` / `quickUnlockDisable` | `Future<void> quickUnlockEnable()` ... | Requires unlocked; user presence prompt shown by the platform |
| `verifyPassword` | `Future<bool> verifyPassword(Uint8List password)` | For re-auth before sensitive actions (view recovery key, export) |

### 4.2 Items and folders (unlocked only; else `locked`)
`list(ListFilter, Page) -> List<ItemSummary>` · `search(SearchQuery) -> List<ItemSummary>` · `itemCount()` ·
`getItem(id) -> ItemView` · `reveal(id, StdField) -> Uint8List?` · `revealCustom(id, ElementId) -> Uint8List?` ·
`createItem(NewItem) -> ItemId` · `setField(id, StdField, String)` · `clearField(id, StdField)` ·
`setFields(id, Map<StdField,String>)` (atomic batch, one transaction) · `toggleFavorite(id)` · `moveToFolder(id, FolderId?)` ·
`addTag/removeTag` · `addUrl/setUrl/removeUrl` · `addCustomField/setCustomValue/setCustomLabel/removeCustomField` ·
`deleteItem(id)` (-> trash) · `restoreItem(id)` · `purgeItem(id)` · `listTrash()` · `emptyTrash()` · `purgeExpired()` ·
`history(id, StdField) -> List<VersionInfo>` · `revealVersion(id, StdField, hlcMs) -> Uint8List?` · `restoreVersion(id, StdField, hlcMs)` ·
`createFolder/renameFolder/deleteFolder/listFolders`.

### 4.3 Generator, strength, health
`generatePassword(PasswordOptions) -> Uint8List` · `generatePassphrase(PassphraseOptions) -> Uint8List` ·
`entropyBits(options) -> double` · `strength(Uint8List) -> Strength` · `checkMasterPassword(Uint8List) -> PolicyResult` (works **while locked**, used in onboarding) ·
`healthReport() -> HealthReport` (unlocked).

### 4.4 Import / export
`importPreview({format, Uint8List file}) -> ImportPreview` (no mutation) · `importCommit({previewToken, options}) -> ImportResult` ·
`exportCsv({AcknowledgePlaintextRisk token}) -> Uint8List` · `exportEncrypted({Uint8List exportPassword}) -> Uint8List` ·
`importEncrypted({Uint8List file, Uint8List exportPassword})`. Files are read/written by Dart (file pickers); the core only sees bytes (bounded by limits, `docs/13`).

### 4.5 Settings
`getSettings() -> AppSettings` · `setSettings(AppSettings)`. App-level (non-vault) settings such as theme/language live in a plain `shared_preferences`-style file owned by Dart; vault-level settings live in the vault `meta` (via core `VaultConfig` and the settings table). Security-relevant values (auto-lock, clipboard seconds) are **clamped by the core** to allowed ranges (auto-lock 1-60 min or "on lock", clipboard 5-120 s).

### 4.6 Diagnostics
`info() -> InfoDto{ coreVersion, formatVersion, schemaVersion, sqlcipherSettings }` · `exportDiagnostics() -> Uint8List` (scrubbed JSON, no vault data; user reviews before sharing).

## 5. State machine
```
NoVault --createVault--> UnlockedPendingConfirm --confirmRecoveryKey--> Unlocked
Locked --unlock/unlockQuick/recoverWithKey--> Unlocked --lock/autolock--> Locked
```
Auto-lock timers, lifecycle (sleep/screen lock) and idle detection are **Dart-owned** and simply call `lock()`. The core additionally enforces: any operation after `lock()` returns `locked`; `lock()` cancels in-flight work.

## 6. Quick unlock (platform seam, in Rust)
Core defines `trait QuickUnlockProvider { fn kind(); fn available(); fn seal(&self, vk: &VaultKey) -> Result<Blob>; fn unseal(&self, blob: &Blob) -> Result<VaultKey>; fn boot_id(&self) -> Option<..> }`. Platform crates implement it in Rust (Windows: Hello-bound `KeyCredentialManager`). The sealed blob and policy state (enabled-at timestamp, failure counter, boot id) live in the vault directory next to the header (never in the cloud). Policy (doc 04 §8): password required after reboot (configurable), 72 h, 5 failures, or invalidation. Dart never sees the VK or the blob.

## 7. Versioning
`API_VERSION` constant in the ffi crate, exposed via `info()`; the Dart side asserts equality at startup (generated bindings and native library must match; a mismatch is a fatal developer error screen).
