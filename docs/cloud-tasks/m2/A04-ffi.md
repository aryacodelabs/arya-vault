# A04: `flutter_rust_bridge` FFI crate

**Branch:** `m2/a04-ffi` · **Depends on:** A01, A02, A03 merged · **Crate:** `core/crates/ffi` (`arya-vault-ffi`) · **Also:** `app/lib/src/rust/` (generated bindings), codegen config · **Reviewer attention:** high (security boundary)

## Context
Read `CLAUDE.md`, `docs/02-architecture.md` §3, §8, `docs/09` ADR-0002, **`docs/14-app-api-contract.md` (all; it is binding)**, `docs/04` §11, `docs/08` (SEC-C06, SEC-H03), the public APIs of `session`, `vault`, `generator`, `crypto::format`/`interchange`. The FFI crate is the thin, security-sensitive translation layer between Dart and Rust.

## Owner-approved exception (recorded here)
`CLAUDE.md` rule 3 allows `unsafe` only in `ffi`/platform glue with maintainer approval. The owner approves `unsafe` **only inside the code generated by `flutter_rust_bridge`** (a single module, e.g. `src/frb_generated.rs`, annotated `#[allow(unsafe_code)]` with a comment pointing to this approval). **All hand-written code in the crate stays under `forbid(unsafe_code)`** (use `#![deny(unsafe_code)]` at the crate root with the single targeted `allow`, since `forbid` cannot be locally relaxed; justify in the PR). Any other `unsafe` is out of bounds: stop and report.

## Deliverables
1. **Rust API module** `api` implementing **every operation, DTO, enum and error in `docs/14` §3-§4** on top of `session`/`vault`/`generator`/interchange. Exactly the names and shapes in the contract. A `const API_VERSION: u32` returned by `info()`. If the contract is impossible or unsafe in some detail, implement the conservative reading and list it under "Spec questions"; do not edit the contract.
2. **Session handle design**: a global `Mutex<Option<Session>>`-style singleton (single vault per process, as assumed) or an opaque handle, whichever the contract implies; all calls serialized; `lock()` zeroizes and drops state; calls after lock return `locked`.
3. **DTO mapping layer** with conversion functions and property tests: **list/summary DTOs contain no secrets by type** (separate Rust structs, no shared "full item" struct that is trimmed afterwards). A test enumerates all fields of `ItemSummary`/`ItemView` and asserts none is secret-bearing.
4. **Secret values** (`reveal*`, `generate*`, recovery key, history values) cross as `Vec<u8>` (Dart `Uint8List`); zero the Rust-side buffers immediately after copying into the return value (note honestly in docs that frb copies; minimise the number of copies; **never** log or `Debug` them).
5. **Error mapping**: `SessionError`/`VaultError`/etc. -> `AppError { code, message, field }` per `docs/14` §2, with `message` scrubbed (a test feeds secrets through error paths and asserts they never appear).
6. **Quick-unlock** plumbing: `quickUnlock*` calls use the session's injected provider; in this crate wire a `NoProvider` by default and expose a `register_quick_unlock_provider(...)` hook (Rust-side, cfg-gated per platform) that L01 uses for Windows. Do not implement real providers.
7. **Codegen**: `flutter_rust_bridge.yaml`, a script `tools/codegen.sh` / `tools/codegen.ps1` generating Dart into `app/lib/src/rust/`, pinned `flutter_rust_bridge` version across Cargo and `pubspec.yaml`, and a **CI check** that regenerated bindings equal the committed ones (job in `ci.yml`, Linux). If the cloud environment cannot install Dart/Flutter, produce the Rust API, config and scripts, state clearly that Dart bindings were **not** generated, and add a TODO for L01; do not hand-write generated code.
8. **Build outputs**: `crate-type = ["cdylib", "staticlib", "rlib"]`; build notes for Windows (cdylib `arya_vault_ffi.dll`) in `crates/ffi/README.md`; release profile keeps `panic = "abort"`: **no panic may cross the boundary**; add `catch_unwind` where frb requires it and tests that panics become `internal` errors (use a test-only panicking function).

## Tests
- Rust integration tests drive the **whole contract** through the `api` module (not through Dart): lifecycle, items, folders, history, search, generator, health, import/export, settings, error codes, state machine (`locked` after `lock`), recovery-key confirmation flow, quick unlock with the `FakeProvider`, key rotation, cross-check that CLI-created vaults open via the API and vice versa.
- Secret-leak tests: error messages, `Debug` output and logs for every API contain no canary secrets; list/search results never contain secret fields.
- Concurrency: calls from multiple threads are serialized without deadlock; `lock()` while another call is mid-flight is safe.
- `API_VERSION` test; golden test that the set of public API function names equals the list in `docs/14` (fail when either side changes alone).
- If Dart is available: a Dart test that loads the built library and runs create -> add item -> search on Linux.

## Out of scope
Real platform providers, Flutter UI, Windows-specific code, sync.
